# Section 0 — Project Framing & Application Scope Checkpoint

| Framing Element | Description |
| :--- | :--- |
| **Problem Evidence** | The public higher education authorities have a wide range of scholarship regulations in different administrative portals, resulting in a large number of inquiries and difficulty navigating through those portals (MOHE Malaysia Guidelines: https://www.mohe.gov.my/). |
| **Existing Approaches** | 1. Consultation with financial aid officers manually (subject to office hours).<br>2. Static PDF manuals (disjointed, difficult to search manually).<br>3. General LLMs (hallucinates income cap eligibility). |
| **Project/Engineering Gap** | There is a need for a natural language query matching to actual policy clauses with references instead of forcing students to filter information from complex financial PDF manually. |
| **Objective 01** | To create an AI system for document-grounded queries using official guidelines for university and foundation scholarships. |
| **Objective 02** | To create a retrieval system with well-defined guardrails ensuring that all answers are grounded in official policy documents. |
| **Objective 03** | To test the system by such metrics as accuracy, grounding in eligibility, latency and rejection of ungrounded financial assertions. |
| **Target Audience** | Undergraduates and prospective university students seeking scholarships, bursaries and financial aid. |
| **Tasks** | Responding to inquiries regarding scholarship eligibility criteria, CGPA minimums, family income cutoff, supporting documents and application deadline dates. |
| **Domain of Information/Knowledge** | Institutional scholarship guides, endowed bursary guidelines, and public financial aid policies. |
| **Operational Context** | Web-based portal for academic advising running as an interactive Q&A agent. |
| **Key Constraints** | Needs to be able to function within the API rate limits, perform at a reasonable speed (<3000ms) and access publicly available PDF documents only. |
| **Explicitly Out-of-Scope Tasks** | Shall NOT approve scholarships, review bank account statements, calculate tax returns and offer personal financial advice. |
| **Focus of Evaluation** | Retrieval-augmented generation effect on citation accuracy and removal of invented eligibility criteria in comparison to base LLMs. |

# Section 1 — Functional Requirements Specification

Version: 1.0

| # | Requirement — The system SHALL | Scope Boundary — SHALL NOT (if applicable) |
| :--- | :--- | :--- |
| **FR1** | Respond to the inquiries about the scholarship eligibility criteria, CGPA cut-off levels and income limits according to the policy documents. | Create any scholarship names, CGPA cut-off and eligibility criteria that are not found in the source documents. |
| **FR2** | Supply the verifiable references for all claims made in the policy documents (name of the document and its page/section). | Give any generalized financial advice as the university policy document. |
| **FR3** | Extract and summarize the submission deadlines and the list of required documents for the application process. | Submit the scholarship applications on the student behalf automatically. |
| **FR4** | Reject the out-of-scope questions (for example career guidance, registration for courses or loan) and provide a proper redirect for them. | Give any legal, tax, personal financial planning and mental counseling advice. |
| **FR5** | Provide the eligibility summaries in an easy-to-understand language by undergraduate students. | Make binding decisions about approving or rejecting the scholarship application. |

# Section 2 — Non-Functional Requirements Specification

| # | Quality Attribute | Requirement | Measurement Approach | Metric | Threshold |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **NFR1** | Performance | The latency for the interactive responses must not exceed the agreed-upon latency threshold. | Measure end-to-end latency between query submission and the generation of the response across a test set of 30 queries. | p90 latency | < 3,000 ms |
| **NFR2** | Correctness | Responses generated by the chatbot must be factually accurate compared to the approved documents. | Score 30 standard financial aid questions on the test set based on the expert evaluation rubric. | Correct response rate (%) | ≥ 85% |
| **NFR3** | Cost | Costs of inference and embeddings API must not exceed project budget constraints. | Track usage of API tokens during the entire test phase. | Cost per 100 queries | < RM 2.20 per 100 queries |
| **NFR4** | Maintainability | New updates in scholarship PDF files should be indexed without needing to reindex other parts of the pipeline. | Measure the time needed to parse, chunk, embed and index newly published PDF file. | Index update time | < 10 minutes |

# Section 3 — Responsible AI Requirements Specification

| # | RAI Risk | Requirement | Measurement Method | Metric | Threshold |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **RAI1** | Fairness | The system answer correctness shall be consistent among various student income brackets or study faculties. | Perform a stratified test set for queries among STEM, Arts and B40/M40 income groups. | Absolute correctness rate difference between groups | ≤ 10 percentage points |
| **RAI2** | Safety / Scope | The system shall reject inappropriate queries including tax avoidance and loan frauds and redirect them accordingly. | Perform a safety test with the minimum of 20 out-of-scope and prompt injection queries. | Rejection-and-redirect success rate | ≥ 95% |
| **RAI3** | Privacy | The system shall not send student PII data to external model API. | Perform inspection of API payloads for IC/Passport numbers, bank accounts, and phone numbers. | Number of PII transmissions discovered | 0 |
| **RAI4** | Transparency / Grounding | The system shall present source citations for all the claims made and notify when insufficient context is available. | Inspect the generated responses for citations and perform source-citation verification. | Citation presence rate which citation-source match rate | 100% citation presence rate which ≥ 95% source-citation match rate |
